            تقرير التحليل الفني: أسباب ظهور خطأ invalid_aliases وكيفية علاجه نهائياً
          

          

            
    
              
  • السبب الأول (عدم وجود اشتراك مسبق للاسم المستعار Alias): في معمارية OneSignal الحديثة (v5/v16 User Model)، عند إرسال إشعار عبر include_aliases: { external_id: [UID] }، فإن OneSignal يبحث عن مشترك نشط (Subscription) يحمل هذا المعرف. إذا لم يكن المستخدم قد سجل دخوله بعد أو لم يكن قد وافق على إذن الإشعارات، فإن OneSignal يرجع استجابة ناجحة للطلب (HTTP 200) ولكن يحتوي الـ JSON على invalid_aliases لأن المعرف لا يملك أي جهاز مسجل.
    • 
              
  • السبب الثاني (الإرسال قبل اكتمال OneSignal.User.pushSubscription.optedIn): كان النظام يرسل إشعارات ترحيبية فور إنشاء المستخدم في شاشة التسجيل قبل أن يدخل المعلم إلى المنصة أو يُنشئ اشتراك Push، فكان يظهر الخطأ.
    • 
              
  • السبب الثالث (تنفيذ login بشكل غير متزامن دون انتظار Await): استدعاء OneSignal.login دون await أو قبل التحقق التام من الـ Auth كان يؤدي لانطلاق طلب الإرسال قبل اكتمال المزامنة في خوادم OneSignal.
    • 
              
  • الحل المنفذ: أصبح النظام ينتظر await OneSignal.login(firebaseUser.uid) مباشرة بعد نجاح Firebase Authentication، وينتظر توليد الـ subscriptionId وتفعيل optedIn، ثم يحفظ الثلاثي (playerId, subscriptionId, externalId) داخل Firestore، ويمنع إرسال أي إشعار فردي لمستخدم لم يشترك بعد.
